# AGENTS.md

This document serves as the primary source of truth for coding agents (AI) operating within this repository. It defines the build environment, code style, and architectural conventions for the personal portfolio website of Justin Yang Chae.

## 1. Project Overview & Environment

*   **Type:** Astro 7 static site (the site was ported from Jekyll — sources preserved under `_jekyll/` for reference).
*   **Astro 7 settings to keep** (`astro.config.mjs`):
    *   `markdown.processor: unified({ remarkPlugins: [...] })` from `@astrojs/markdown-remark`. Astro 7's default Markdown processor is Sätteri, which cannot run the remark plugins this site depends on (`remark-math`, `remark-directive`, `remark-mathjax.js`, `remark-trace-directives.js`). MDX inherits the processor. Add new remark/rehype plugins to `unified({ ... })`, not to the deprecated `markdown.remarkPlugins`; switching to Sätteri means porting every plugin first.
    *   `compressHTML: true`. Astro 7's default (`'jsx'`) drops whitespace between inline elements on separate lines, which glues together the chips, the post header's date/`·`/reading time, and the home page's `focus: … · also: …` line. Don't remove it.
    *   Import Zod from `astro/zod` (Zod 4), not `astro:content`; custom messages use `{ error: '…' }`.
*   **Hosting:** GitHub Pages via GitHub Actions (`.github/workflows/deploy.yml`, `withastro/action`). The repo's Pages source must stay set to **GitHub Actions** (`build_type: workflow`) — the legacy "deploy from branch" mode runs a Jekyll build that fails on `.astro` front matter. Keep `cache: false` on `withastro/action`: its restored content cache would keep serving deleted posts. Pull requests into `main` run the build job only (the deploy job is skipped), so a broken build fails the PR before it can ship. When the `DRAFTS_DEPLOY_KEY` secret is set (a read-only deploy key on the private `blog-drafts` repo), the build job checks that repo out into `drafts/` (`persist-credentials: false`) and `::add-mask::`s every share token, because the build log and the artifact upload list each page and this repo's Actions logs are public; without the secret (forks, Dependabot) it builds without shared drafts, and the checkout step has `continue-on-error` so a bad key or unreachable drafts repo can't block site deploys (shared links just 404 until it's fixed; the step's annotation shows why). Keep the mask step before the build if you touch the workflow.
*   **Structure:**

    *   `src/components/` — `PostChips.astro` (draft/category/tag chips: blog index, tag pages, post header) and `PostList.astro` (the listing on the blog index and tag pages). Edit chips/listings there, not per page.
        *   **Site nav** (`Base.astro`): the same three page links on every page — Home / Violin / Blog — with the current page marked server-side via the `activeNavLink` prop (`'home' | 'violin' | 'blog'` → `.active` + `aria-current="page"`). The user removed the `justin-chae:~$` brand wordmark and the home-page section anchor links (About/Education/…); do not reintroduce them — sections stay reachable via `:about` etc.
    *   `src/content/blog/` — posts as `.md` or `.mdx` (MDX enabled: posts can import components). Keep the `.gitkeep`: with zero posts `/blog/` renders its empty state, no post/tag pages are generated, and the build's `[glob-loader] No files found` warning (plus Astro's `The collection "blog" does not exist or is empty` notices, and one for `"drafts"` when no draft is shared) is expected. Locally, Astro's content cache (`node_modules/.astro/`) keeps serving deleted posts when the folder ends up empty — use `npx astro build --force` after removing posts.

### Blog posts

*   Files: `src/content/blog/<slug>.md` (or `.mdx`) with `title`, `description`, `date`, optional `category` (single chip, gold) and optional `tags: [...]` (multiple chips, iris; must be kebab-case — tags become URL segments, and the schema in `content.config.ts` rejects anything else) front matter. Output URL: `/blog/<slug>/`. The blog index and post header both render the category + tag chips, and **tag chips link to `/blog/tag/<tag>/`** listing pages (generated automatically for every tag in use). The blog index and `sitemap.xml` update automatically. No RSS feed — the user explicitly removed it; do not reintroduce feeds. Optional `comments: false` hides the comments section.
*   **Drafts:** the `drafts` collection (`content.config.ts`) globs all of `drafts/` only when `import.meta.env.ASTRO_SHOW_DRAFTS === 'true'`, which the `drafts-gate` integration in `astro.config.mjs` defines from the CLI command (true only for `astro dev`). Every other command loads only **shared drafts** (below), or clears the collection when there are none, and `getPosts()` checks the same flag, so unshared drafts can never ship and shared ones never reach a listing. Do NOT gate on `import.meta.env.DEV`: it is just `NODE_ENV !== 'production'`, so `NODE_ENV=development astro build` or `--devOutput` would publish every draft. Drafts render with a `.chip-draft` (love) chip + `.draft-note` and no comments. Workflow: `npm run draft:new -- <slug> "Title"` → preview under `npm run dev` → `npm run drafts:sync` (pull/commit/push the private repo) → `npm run draft:publish -- <slug>` (moves it into `src/content/blog/`, sets `date:` to today unless `--keep-date`) → commit + push the site. The sitemap reads only the `blog` collection.
*   **Shared drafts (unlisted links):** `npm run draft:share -- <slug>` writes `share: "<token>"` (20 random hex chars; the schema requires `^[a-z0-9]{16,64}$`) into a draft's front matter; after `drafts:sync` and a deploy (`workflow_dispatch` or a push to `main`), the draft is live at `/drafts/<token>/`. `--rotate` replaces the token, `--revoke` removes it, no argument lists shared drafts. Outside `astro dev`, `content.config.ts` globs only the files `shared-drafts.mjs` finds with a `share:` line, read before the glob runs, so an unfinished unshared draft can't break the deploy (a broken *shared* draft does). `src/pages/drafts/[token].astro` renders them through `Post.astro` with `shared`: `noindex`, no `canonical`/`og:url`/`article:published_time`, no comments, no related posts or older/newer links, tag chips as plain spans (a draft's tag may have no tag page), and a "shared by link" `.draft-note`. They never appear in the blog index, tag pages, sitemap, or related posts; never add `/drafts/` to `robots.txt` (crawlers must fetch the page to see `noindex`). `draft:publish` strips the `share:` line so tokens never reach this public repo. It is unlisted, not access-controlled: anyone with the link can read it, and the build artifact is downloadable from the run for a day. Everything a shared draft uses from this repo (`@/` components, `src/data/<slug>.json`, `/assets/` images) must be committed and pushed first, since CI builds from GitHub; `draft:share` warns about any `@/` import or `/assets/` path that `git ls-files` doesn't track.
*   **Trace viewer (`/traces/<post>/`):** a post's full agent runs, one page per run. Data is one JSON file per run in `src/data/traces/<post>/<run>.json` (types in `src/lib/traces.ts`), exported from the raw run dumps by a script kept with the draft in the private drafts repo: it counts each agent turn once (dropping pending/completed duplicates and blocks the dump replayed), trims tool output over 3,000 characters, removes email addresses, leaves out each harness's own system prompt, and links every `self_score` job to the turn that launched it and the entry where its result came back. A post's runs only publish once listed in `TRACE_POSTS`. `src/components/TraceSwitch.astro` links a post and its traces: `Post.astro` puts it under the date of any post in `TRACE_POSTS` as a callout box (`.ts-on-post`: "Read the agent traces →" for the index, then a pill per run; styled apart from the tag chips so it reads as a link), and every trace page puts it at the top with the current run marked and "← the post". Until the post is published that link has no URL to use (the shared draft's token must never be written into these public pages), so it reads "← blog" (the index); the post's row carries `data-trace-home`, `script.js` §14 saves that page's path in `localStorage` (`trace-back:<post>`), and on trace pages it turns the link into "← the post" pointing there, so a reader who came from the share link can go back. The index shows one card per run; a run page has its stats, a jobs table, the task prompt, then an `<ol class="tv-log">` of entries: turns (`#turn-N`: thinking where the harness kept it, the agent's message, each tool call with its output in a closed `<details>`), environment notices, compaction markers and context summaries (`#e-N`). Agent-written text (messages, thinking, summaries, the task prompt) renders as markdown at build time through `src/lib/trace-markdown.ts`, Astro's own unified pipeline treated as untrusted input: tag-like `<` is escaped outside code before parsing (a line opening with `<summary>` would otherwise start an HTML block), any raw HTML left becomes literal text, links keep only http(s) and `#` anchors (`rel="nofollow noopener noreferrer"`), images become links, headings become bold `p.tv-md-h` lines with no ids (so they stay out of the outline and can't clash with `#turn-N`), single newlines stay `<br>`, and there's no SmartyPants or Shiki (the text reads as written, and Shiki's inline styles would break the strict CSP). Tool calls, output and environment notices stay preformatted. `script.js` §14 un-hides the toolbar: a focus mode (`.tv-log.is-focus` hides `.tv-routine`: tool calls that aren't a `self_score` launch or result, and turns with nothing else) and a jump-to-turn box; a hash that focus would hide switches back to every step. The toolbar is sticky under the nav, at the top below 768px (where the nav scrolls away) and not sticky below 600px. Until the post is published the pages are `noindex`, have no canonical URL, and link to the post only under `astro dev`. The pages are 0.3–1.2 MB of HTML, so keep the output cap when adding runs.
*   **Drafts editor (`scripts/drafts-editor/`, dev only):** `npm run dev`, then `http://localhost:4321/edit/[<slug>]`. The `drafts-editor` integration in `astro.config.mjs` (listed before `mdx()`) does nothing outside `astro dev`: it appends `remarkSourceLines` to the `unified({...})` processor's `remarkPlugins` (Astro 7 reads that array when .md and .mdx first render; the plugin tags rendered blocks with `data-line`/`data-line-end`; `.md` drafts are numbered from the body, `.mdx` from the file), pre-bundles CodeMirror, and mounts middleware at `/edit/`: the editor page (plain HTML without the Vite client, so Astro's `full-reload` on every content change can't reset it), `/edit/preview/<slug>/` (`/blog/<slug>/` minus the Vite client and dev toolbar, so the editor controls reloads), and a JSON API under `/edit/api/` (list/read/save/create drafts, check MDX, upload images to `public/assets/blog/<slug>/`). Writes require the `X-Drafts-Editor: 1` header; saves send the hash the editor last saw and get a 409 when the file changed on disk. The middleware wraps `server.ws.send` to forward Astro's `full-reload` (and error payloads) to the editor over server-sent events (`/edit/api/events`), and watches `drafts/` for outside edits. `client.js` (bundled by Vite) double-buffers two preview iframes and swaps in each new render at the reader's place; parse problems come from `@mdx-js/mdx` with GFM plus the site's own remark plugins (for their syntax, e.g. remark-math) and Astro's own front matter parser. The parsers load inside `astro:server:setup`, so `astro build` never imports them. Vim keys come from `@replit/codemirror-vim` (on by default, a toolbar checkbox turns them off, `:w` saves); `vim()` must stay the first extension, and code that inserts text for the user to type into calls `enterInsertMode` first. The "+ new" template must match `scripts/new-draft.mjs`. Astro doesn't restart when these files change; restart `npm run dev` after editing `integration.mjs`.
*   **Comments:** [giscus](https://giscus.app) — GitHub Discussions in this repo's **Announcements** category. Each thread is keyed by `data-mapping="specific"` + `data-term="blog/<slug>/"` (`data-strict="1"`), and a `giscus:backlink` meta pins the discussion's link to the canonical URL — so `/index.html`, query strings, or localhost previews never fork or mislabel a thread. Never change the term format, or existing threads detach from their posts. Upvotes are 👍 reactions, replies go one level deep, moderation happens on GitHub. The giscus GitHub app must stay installed on the repo. `Post.astro` renders `section.post-comments > div.giscus#giscus-thread[data-*]` (the id makes GitHub sign-in return to the comments); `script.js` §9 injects `https://giscus.app/client.js` when the panel nears the viewport (immediately when the URL carries `?giscus=` on return from sign-in), copying the `data-*` config onto that `<script>` (client.js reads `document.currentScript.dataset`). The comments panel is excluded from scroll-reveal. The custom theme `public/assets/giscus-rose-pine.css` is passed as an absolute **production** URL (`?v=<commit>` in CI) because giscus fetches it from inside its iframe — so theme edits only show up after a deploy. The theme hooks giscus's `#__next`/`gsc-*` markup; recheck it after giscus updates. On posts that render comments (`Base.astro` `comments` prop), the `post` CSP allows `https://giscus.app` in `script-src`, `style-src` (client.js links `giscus.app/default.css`) and `frame-src`; keep that in sync if the embed changes.
*   **Math:** write `$$…$$` in markdown. `remark-math` (`singleDollarTextMath: false`, so a lone `$` stays a dollar sign) parses it like kramdown did: inside a sentence it is inline math; a fenced `$$` block, or a paragraph holding nothing but one `$$…$$`, is display math. `src/plugins/remark-mathjax.js` emits the TeX verbatim as `span.math-inline` `\(…\)` / `div.math-display` `\[…\]`, so backslash escapes (`\;` `\{` `\\`) and `_…_` are safe — write plain LaTeX, never doubled backslashes. It renders client-side by the **self-hosted MathJax 3.2.2 SVG** bundle (`/assets/mathjax/tex-svg.js` + `/assets/mathjax-config.js`, which also accepts `$$…$$` for math in raw HTML). `Post.astro` loads the 2 MB bundle only on posts that contain math (`remarkPluginFrontmatter.hasMath`, set by the plugin). `tsconfig.json` excludes the bundle — type-checking it runs `astro check` out of memory.
*   **Math in `.mdx`:** MDX treats `{ }` as JavaScript, so `$$…$$` with braces breaks there. Use `<Tex tex="p" />` (inline, emits `\(…\)`) or `<Tex block tex={String.raw`…`} />` (display, emits `\[…\]`) from `@/components/blog/Tex.astro`. Also in MDX: no `<!-- -->` comments (use `{/* */}`) and no bare `<` in prose.
*   **Figures (`src/components/blog/`, `.mdx` posts):** `LineChart`, `BarChart`, `Columns`, `Grid` (two-up small multiples, or three-up with `cols={3}`; one column on phones), `Fold` (collapsible optional section, e.g. prerequisites), `Tex`, and post-specific diagrams (`SelfPlayLoop`, and its animated version `SelfPlayAnimation`, driven by `script.js` §12; ## 2. Code Style & Conventions

### HTML (`.astro`)

*   **Indentation:** Use **Tabs**.
*   **Semantics:** deeply prioritized. Use `<nav>`, `<header>`, `<main>`, `<section>`, `<footer>` appropriately.
*   **Attributes:** double quotes; `alt` mandatory for images; `aria-label` for interactive elements without text labels.
*   **Performance:** lazy loading for below-the-fold images; explicit `width`/`height`; hero image keeps `fetchpriority="high"`. YouTube embeds must use the lite pattern (`.video-placeholder` + click-to-load in `script.js`).
*   **Security:** every page sets a `Content-Security-Policy` `<meta>` via `Base.astro` (`strict` for non-post pages; `post` adds `style-src 'unsafe-inline'` for MathJax/Shiki inline styles). External resources require updating the CSP. No inline `style=""` in authored markup; scripts load from `/script.js` (or `is:inline src=` files only).

### CSS (`public/home.css`)

*   **Theme:** Rosé Pine (main variant, https://rosepinetheme.com), terminal-flavored. Dark only, clean flat surfaces — NO CRT effects (scanlines/vignette/grain/glows/gridlines were deliberately removed). All colors via CSS variables in `:root`:
    *   Surfaces: `--bg` (#191724 base), `--bg-raised` (#1f1d2e surface), `--bg-inset` (#26233a overlay)
    *   Text: `--text` (#e0def4), `--subtle` (#908caa), `--muted` (#6e6a86); lines: `--border` (#403d52), `--border-bright` (#524f67)
    *   Accents: `--rose` (#ebbcba cursor/active/h2/focus), `--gold` (#f6c177 dates/labels/chips), `--iris` (#c4a7e7 links), `--foam` (#9ccfd8 mode block/keywords), `--pine` (#31748f quiet structure), `--love` (#eb6f92 errors/404)
    *   Stick to this mapping when adding components; do not reintroduce glows or textured backgrounds.
    *   Charts use the separate `--chart-*` tokens instead: the raw accents are too light and too gray to tell apart as data marks (see **Figures** above).
*   **Type pairing:** `--font-display` (Departure Mono) for headings/nav/statusline; `--font-body` (CommitMono Nerd Font) for copy. ALL fonts are self-hosted subset woff2 in `/assets/fonts/` (see its README) — **never load fonts from Google Fonts**: the site sits behind Cloudflare, whose "Cloudflare Fonts" feature rewrites Google Fonts links into inline `<style>` blocks that the strict CSP blocks (this broke headings in production once). Departure Mono has one weight — never apply `bold` to display type. CommitMono ships 400/700 only — use `font-weight: 700` for bold, never 600.
*   **Korean text:** `assets/fonts/NanumGothicCoding-name.woff2` contains ONLY the three glyphs 채정인. If you add any other Korean text, re-subset it with wider `--unicodes` (see `assets/fonts/README.md`).
*   **Units:** `rem` for font sizes/padding; kebab-case class names; multi-line rules.
*   **Motion:** every animation/transition must have a `prefers-reduced-motion: reduce` override.
*   **Scrollbar gutter:** `html` keeps `scrollbar-gutter: stable`. Without it, short pages (an empty blog, the 404) have no scrollbar and the centered nav and panels shift 5px sideways versus long pages.
*   **Profile photo:** stays in full color — no grayscale/desaturate filter (explicit user request); hover only adds the rose border + shadow.
*   **Cache-busting:** `Base.astro` appends `assetVersion` (`?v=<commit>` from `GITHUB_SHA`, defined in `src/lib/site.ts`) to `/home.css` and `/script.js`, and `Post.astro` to the giscus theme URL, because Cloudflare caches them in browsers for hours. Keep it if you move or rename any of them.

### JavaScript (`public/script.js`)

*   **Indentation:** 4 spaces. Modern vanilla ES6+ (`const`/`let`, arrow functions, template literals, single quotes, semicolons required).
*   **Execution:** wrap logic in `document.addEventListener('DOMContentLoaded', ...)`.
*   **Progressive enhancement:** the site must remain fully readable with JS disabled (typed boot line falls back to static text, sections fall back to visible).
*   **Observers:** Use `IntersectionObserver` for scroll-based effects; throttle scroll handlers with `requestAnimationFrame`.

## 3. Architecture & Patterns

### Interactivity (public/script.js)
*   **Centralization:** All interactivity lives in `public/script.js` (shared by every Astro page). No inline JS in HTML.
*   Features: typed boot line, scroll reveal, lite YouTube embeds, lite X embeds (on post pages, an `x.com`/`twitter.com` `/<user>/status/<id>` link that stands alone in its paragraph becomes a click-to-load placeholder; links inside a sentence stay links; hosts are matched exactly, not by substring; the `post` CSP allows the platform.twitter.com frame), back-to-top, statusline scroll position + showcmd, and vim keyboard navigation (`j`/`k` scroll, `d`/`u` half page, `gg`/`G` top/bottom, `h`/`l` previous/next page, `?` help overlay, `Esc` close). The keydown handler must keep ignoring modifier combos, IME composition, and form fields, and the help overlay is built with `createElement` (no `innerHTML`, no inline styles — CSP) and keeps `Tab` inside while open. Scroll reveal applies to `main > section` panels only (never post-content sections such as footnotes) and triggers via a `rootMargin`, not a visibility ratio, so panels taller than the viewport still reveal; print CSS forces unrevealed panels visible. Clipboard writes go through one `copyText()` helper (async API, `execCommand` fallback). On the 404 page `script.js` echoes the requested path into `.err-path`.
*   **Vim command mode (`:`):** pressing `:` opens an ex-style command line docked above the statusline (mode block shows `CMD`). Commands: `:about`/`:education`/`:papers`/`:projects`/`:achievements` scroll to sections (navigating to `/index.html#<section>` first when on another page), `:music`/`:blog`/`:home` navigate pages, `:email` copies the contact address to the clipboard, `:cv` opens the CV PDF in a new tab, `:linkedin`/`:scholar`/`:github`/`:x`/`:twitter` open those profiles in a new tab (`noopener`), `:help` opens the key overlay, `:ls` lists sections, `:top`/`:bottom` (+ `:1`/`:$`) scroll, `:noh`/`:nohlsearch` clears search highlights, and `:q`/`:q!`/`:wq` are deliberate easter eggs. Like vim, `Enter` runs the line and returns to normal mode; `Esc` or clicking elsewhere on the page also closes it (switching windows does not). Supports `↑`/`↓` history (consecutive duplicates collapsed) and `Tab` prefix completion with candidate list. `closeCommandLine()` blurs the input explicitly — browsers only move focus off a hidden element on the next frame, which swallowed fast keystrokes. Unknown commands echo `E492: not an editor command: <name>` in the `--love` color. Feedback is echoed into `#showcmd` (`.flash-msg`/`.err` classes) AND mirrored into a `.visually-hidden` `aria-live` region — keep both when editing.
*   **Vim search (`/`, `n`, `N`):** `/` opens the same docked command line in SEARCH mode; Enter runs a case-insensitive substring search over `<main>` text and wraps hits in `mark.search-hit` (`.current` = rose; `n`/`N` cycle and auto-open collapsed `details`/reveal hidden sections; empty Enter reuses the last pattern). Misses echo `E486: pattern not found`, `n` with no prior search echoes `E35`. Highlights clear via `:noh` or a new page load. Keep the `prefers-reduced-motion` (pulse) and print (transparent) overrides when editing.
*   **Blog trace blocks (Prime Intellect-style):** in a post, wrap code blocks or prose in directive containers — `:::tool-call` / `:::tool-output` / `:::annotation` / `:::reasoning` (starts collapsed) / `:::bibtex` (unnumbered) / `:::tldr` — and the `remarkTraceDirectives` plugin puts the class on the wrapper. On post pages `script.js` wraps each container in a numbered collapsible `details.trace-block` panel (steps run in document order across mixed code/prose; every type accepts prose, which gets the padded `.trace-prose` well) and every `pre` gets an overlay `[copy]` button (`.copied`/`.err` feedback states). Footnotes via `[^1]`/`[^1]: text` (GFM) render as a `~/footnotes` well; the CSS targets GFM's markup (`section.footnotes`, `a[data-footnote-ref]`, `a[data-footnote-backref]`, the `.sr-only` heading), not kramdown's. Plain code blocks stay unnumbered. Without JS everything degrades to normal code blocks/paragraphs.
*   **Blog chart hover (`script.js` §11):** `LineChart` figures carry a `data-chart` payload (pixel positions plus preformatted values). `script.js` adds a crosshair + tooltip on pointer or keyboard focus (←/→ step through points, Esc hides) and writes text with `textContent` only. Without JS the static chart remains.
*   **Animated diagrams (`script.js` §12):** `SelfPlayAnimation` draws the complete static diagram in markup; script.js adds `.sp-live` and runs one clock over `data-cycle` seconds, toggling `.is-shown` (from `data-on`/`data-off`), `.is-active` (from `data-active="start end"`, which may list several pairs), moving packets (`data-travel` + `data-route` points) and typed text (`data-type="start end"`: the element's text is read once, then revealed character by character over that window). Pause/restart only move the clock; it plays while ≥35% on screen. Under `prefers-reduced-motion` (or without JS) nothing runs and the static diagram stays. `AgentReplay` uses the same clock (`.sp-anim`), mapping agent turns linearly to seconds (its data gives each job's launch and result turn, plus the same moments in hours), with a `data-ease="linear"` playhead; its static state is the end of the run (CSS hides every `.ar-frame` and `.ar-best` but the `.ar-final` one until `.sp-live`). Its controls carry a `.sp-scrub` range input (`step="any"` so the thumb glides; script.js handles keys itself: arrows 2% of the loop, Page keys 10%, Home/End; it pauses while dragging, keeps a 0.12s fade, and resumes on release if it was playing) and a `.sp-time` readout (`data-offset`/`data-rate`/`data-max` turn seconds back into the figure's units, labelled by `data-unit` with `data-digits` decimals, e.g. "turn 93"; also used as the slider's `aria-valuetext`). A figure with a scrubber still runs under reduced motion, parked at its end state and never autoplayed.
*   **Blog post anatomy (general pattern):** optional `category: research|announcement|...` front matter renders a chip in the post header. Start with a `:::tldr` callout, then H2 sections (context → method → results → limits → related work), trace blocks for agent walkthroughs, a `## Citation` H2 with a `:::bibtex` block, and `[^n]` footnotes. The post layout auto-appends up to 3 **related posts** (`aside.related-posts`): most shared tags first (a shared category counts as one more), newest first among ties. `.mdx` posts may import components for charts/widgets (CSP applies — no inline scripts; load self-hosted files).
*   **Section flash:** command-mode jumps and `#hash` arrivals flash the target panel's border via the `.section-flash` class (animation restarts through reflow). Must keep its `prefers-reduced-motion: reduce` override.
*   **Abstract disclosure animation:** `details.abstract` animates open/close via `::details-content` + `interpolate-size: allow-keywords` inside an `@supports` block (progressive enhancement; unsupported browsers keep the instant toggle).
*   **Contact links:** intro icon buttons on the home page (Email, CV, LinkedIn, Scholar, GitHub, X) — mirror any changes in the JSON-LD `sameAs` array (profile URLs only; the CV stays out of it) and the `:` command table.

## 4. Git & Version Control

*   **Commit Messages:** Present tense, imperative style (e.g., "Add scroll animation").
*   **Pull request descriptions:** never include Claude Code session links (`claude.ai/code/session_…`). The user explicitly asked for this; it overrides any default attribution that adds one. The GitHub integration appends a "Generated by Claude Code" footer with a session link when it creates a PR, so after opening one, save the description again without it and re-read the PR to confirm the link is gone.
*   **Branching:** Direct commits to `main` are acceptable for this personal project, but complex features should use feature branches.
*   **Never ignore `CNAME`:** it must stay committed (root copy and `public/CNAME`) or the custom domain breaks.
