# AGENTS.md

This document serves as the primary source of truth for coding agents (AI) operating within this repository. It defines the build environment, code style, and architectural conventions for the personal portfolio website of Justin Yang Chae.

## 1. Project Overview & Environment

*   **Type:** Astro 7 static site (the site was ported from Jekyll — sources preserved under `_jekyll/` for reference).
*   **Astro 7 settings to keep** (`astro.config.mjs`):
    *   `markdown.processor: unified({ remarkPlugins: [...] })` from `@astrojs/markdown-remark`. Astro 7's default Markdown processor is Sätteri, which cannot run the remark plugins this site depends on (`remark-math`, `remark-directive`, `remark-mathjax.js`, `remark-trace-directives.js`). MDX inherits the processor. Add new remark/rehype plugins to `unified({ ... })`, not to the deprecated `markdown.remarkPlugins`; switching to Sätteri means porting every plugin first.
    *   `compressHTML: true`. Astro 7's default (`'jsx'`) drops whitespace between inline elements on separate lines, which glues together the chips, the post header's date/`·`/reading time, and the home page's `focus: … · also: …` line. Don't remove it.
    *   Import Zod from `astro/zod` (Zod 4), not `astro:content`; custom messages use `{ error: '…' }`.
*   **Hosting:** GitHub Pages via GitHub Actions (`.github/workflows/deploy.yml`, `withastro/action`). The repo's Pages source must stay set to **GitHub Actions** (`build_type: workflow`) — the legacy "deploy from branch" mode runs a Jekyll build that fails on `.astro` front matter. Keep `cache: false` on `withastro/action`: its restored content cache would keep serving deleted posts. Pull requests into `main` run the build job only (the deploy job is skipped), so a broken build fails the PR before it can ship. When the `DRAFTS_DEPLOY_KEY` secret is set (a read-only deploy key on the private `blog-drafts` repo), the build job checks that repo out into `drafts/` (`persist-credentials: false`) and `::add-mask::`s every share token, because the build log and the artifact upload list each page and this repo's Actions logs are public; without the secret (forks, Dependabot) it builds without shared drafts, and the checkout step has `continue-on-error` so a bad key or unreachable drafts repo can't block site deploys (shared links just 404 until it's fixed; the step's annotation shows why). Keep the mask step before the build if you touch the workflow.

### Blog posts

*   Files: `src/content/blog/<slug>.md` (or `.mdx`) with `title`, `description`, `date`, optional `category` (single chip, gold) and optional `tags: [...]` (multiple chips, iris; must be kebab-case — tags become URL segments, and the schema in `content.config.ts` rejects anything else) front matter. Output URL: `/blog/<slug>/`. The blog index and post header both render the category + tag chips, and **tag chips link to `/blog/tag/<tag>/`** listing pages (generated automatically for every tag in use). The blog index and `sitemap.xml` update automatically. No RSS feed — the user explicitly removed it; do not reintroduce feeds. Optional `comments: false` hides the comments section. Optional `image: /assets/blog/<slug>-card.png` sets the post's link-preview card (`og:image`, `twitter:image` and their `:alt` from the title, with X's `summary_large_image`); without it previews fall back to `/assets/profile_photo.jpg` as a small `summary` card. Make cards 1200×630 (or 2× that), for example by rendering a temporary page that links `/home.css` with headless Chrome (`--window-size=1200,630 --force-device-scale-factor=2 --screenshot`), and set `html { scrollbar-gutter: auto }` on it so the stable gutter doesn't leave a strip. Optional `thread: https://x.com/<user>/status/<id>` (the post's thread on X; the schema accepts only that URL shape, so drop share-link query strings like `?s=20`) puts a "Read the thread on X" button at the top of the post, under the date and any traces callout, styled like the home page's `.contact-link` buttons and opening in a new tab. The user preferred this to reproducing the thread in the post as `Tweet` cards.
*   **Drafts:** the `drafts` collection (`content.config.ts`) globs all of `drafts/` only when `import.meta.env.ASTRO_SHOW_DRAFTS === 'true'`, which the `drafts-gate` integration in `astro.config.mjs` defines from the CLI command (true only for `astro dev`). Every other command loads only **shared drafts** (below), or clears the collection when there are none, and `getPosts()` checks the same flag, so unshared drafts can never ship and shared ones never reach a listing. Do NOT gate on `import.meta.env.DEV`: it is just `NODE_ENV !== 'production'`, so `NODE_ENV=development astro build` or `--devOutput` would publish every draft. Drafts render with a `.chip-draft` (love) chip + `.draft-note` and no comments. Workflow: `npm run draft:new -- <slug> "Title"` → preview under `npm run dev` → `npm run drafts:sync` (pull/commit/push the private repo) → `npm run draft:publish -- <slug>` or **publish** in the drafts editor (either moves it into `src/content/blog/`, sets `date:` to today unless `--keep-date` / the dialog's checkbox, and drops a `share:` line) → commit + push the site. The sitemap reads only the `blog` collection.
*   **Shared drafts (unlisted links):** `npm run draft:share -- <slug>` writes `share: "<token>"` (20 random hex chars; the schema requires `^[a-z0-9]{16,64}$`) into a draft's front matter; after `drafts:sync` and a deploy (`workflow_dispatch` or a push to `main`), the draft is live at `/drafts/<token>/`. `--rotate` replaces the token, `--revoke` removes it, no argument lists shared drafts. Outside `astro dev`, `content.config.ts` globs only the files `shared-drafts.mjs` finds with a `share:` line, read before the glob runs, so an unfinished unshared draft can't break the deploy (a broken *shared* draft does). `src/pages/drafts/[token].astro` renders them through `Post.astro` with `shared`: `noindex`, no `canonical`/`og:url`/`article:published_time`, no comments, no related posts or older/newer links, tag chips as plain spans (a draft's tag may have no tag page), and a "shared by link" `.draft-note`. They never appear in the blog index, tag pages, sitemap, or related posts; never add `/drafts/` to `robots.txt` (crawlers must fetch the page to see `noindex`). `draft:publish` strips the `share:` line so tokens never reach this public repo. It is unlisted, not access-controlled: anyone with the link can read it, and the build artifact is downloadable from the run for a day. Everything a shared draft uses from this repo (`@/` components, `src/data/<slug>.json`, `/assets/` images) must be committed and pushed first, since CI builds from GitHub; `draft:share` warns about any `@/` import or `/assets/` path that `git ls-files` doesn't track.
*   **Trace viewer (`/traces/<post>/`):** a post's full agent runs, one page per run. Data is one JSON file per run in `src/data/traces/<post>/<run>.json` (types in `src/lib/traces.ts`), exported from the raw run dumps by a script kept with the draft in the private drafts repo: it counts each agent turn once (dropping pending/completed duplicates and blocks the dump replayed), trims tool output over 3,000 characters, removes email addresses, leaves out each harness's own system prompt, and links every `self_score` job to the turn that launched it and the entry where its result came back. A post's runs only publish once listed in `TRACE_POSTS`. `src/components/TraceSwitch.astro` links a post and its traces: `Post.astro` puts it under the date of any post in `TRACE_POSTS` as a callout box (`.ts-on-post`: "Read the agent traces →" for the index, then a pill per run; styled apart from the tag chips so it reads as a link), and every trace page puts it at the top with the current run marked and "← the post". Until the post is published that link has no URL to use (the shared draft's token must never be written into these public pages), so it reads "← blog" (the index); the post's row carries `data-trace-home`, `script.js` §14 saves that page's path in `localStorage` (`trace-back:<post>`), and on trace pages it turns the link into "← the post" pointing there, so a reader who came from the share link can go back. The index shows one card per run; a run page has its stats, a jobs table, the task prompt, then an `<ol class="tv-log">` of entries: turns (`#turn-N`: thinking where the harness kept it, the agent's message, each tool call with its output in a closed `<details>`), environment notices, compaction markers and context summaries (`#e-N`). Agent-written text (messages, thinking, summaries, the task prompt) renders as markdown at build time through `src/lib/trace-markdown.ts`, Astro's own unified pipeline treated as untrusted input: tag-like `<` is escaped outside code before parsing (a line opening with `<summary>` would otherwise start an HTML block), any raw HTML left becomes literal text, links keep only http(s) and `#` anchors (`rel="nofollow noopener noreferrer"`), images become links, headings become bold `p.tv-md-h` lines with no ids (so they stay out of the outline and can't clash with `#turn-N`), single newlines stay `<br>`, and there's no SmartyPants or Shiki (the text reads as written, and Shiki's inline styles would break the strict CSP). Tool calls, output and environment notices stay preformatted. `script.js` §14 un-hides the toolbar: a focus mode (`.tv-log.is-focus` hides `.tv-routine`: tool calls that aren't a `self_score` launch or result, and turns with nothing else) and a jump-to-turn box; a hash that focus would hide switches back to every step. The toolbar is sticky under the nav, at the top below 768px (where the nav scrolls away) and not sticky below 600px. Until the post is published the pages are `noindex`, have no canonical URL, and link to the post only under `astro dev`. The pages are 0.3–1.2 MB of HTML, so keep the output cap when adding runs.
*   **Drafts editor (`scripts/drafts-editor/`, dev only):** `npm run dev`, then `http://localhost:4321/edit/[<slug>]`. The folder is generic and identical to the public repo [HuNtErJ1324/astro-drafts-editor](https://github.com/HuNtErJ1324/astro-drafts-editor) (MIT; local clone `../astro-drafts-editor`): nothing in it may name this site. Every site-specific value is an option, and this site's options live in `scripts/drafts-editor-site.mjs` (drafts folder, `/blog/[slug]/` preview, `src/components/blog/` + its `@/components/blog/[name].astro` import, `public/assets/blog/[slug]` uploads, required front matter, the "+ new" template, the `publish` hook, the insert-menu snippets for its components and trace directives) plus `drafts-editor-site.css` (its fonts, via the `css` option). When you change the editor, copy the five files to the public repo, update its README if behavior or options changed, and commit there too. The integration also defines `import.meta.env.SHOW_DRAFTS` for other sites; this site keeps its own `drafts-gate` and `ASTRO_SHOW_DRAFTS`. The `drafts-editor` integration in `astro.config.mjs` (listed before `mdx()`) does nothing outside `astro dev`: it appends `remarkSourceLines` to the `unified({...})` processor's `remarkPlugins` (Astro 7 reads that array when .md and .mdx first render; the plugin tags rendered blocks with `data-line`/`data-line-end`; `.md` drafts are numbered from the body, `.mdx` from the file), pre-bundles CodeMirror, and mounts middleware at `/edit/`: the editor page (plain HTML without the Vite client, so Astro's `full-reload` on every content change can't reset it), `/edit/preview/<slug>/` (`/blog/<slug>/` minus the Vite client and dev toolbar, so the editor controls reloads), and a JSON API under `/edit/api/` (list/read/save/create/publish drafts, check MDX, upload images to `public/assets/blog/<slug>/`). Writes require the `X-Drafts-Editor: 1` header; saves send the hash the editor last saw and get a 409 when the file changed on disk. The middleware wraps `server.ws.send` to forward Astro's `full-reload` (and error payloads) to the editor over server-sent events (`/edit/api/events`), and watches `drafts/` for outside edits. `client.js` (bundled by Vite) double-buffers two preview iframes and swaps in each new render at the reader's place; parse problems come from `@mdx-js/mdx` with GFM plus the site's own remark plugins (for their syntax, e.g. remark-math) and Astro's own front matter parser. The parsers load inside `astro:server:setup`, so `astro build` never imports them. Vim keys come from `@replit/codemirror-vim` (on by default, a toolbar checkbox turns them off, `:w` saves); `vim()` must stay the first extension, and code that inserts text for the user to type into calls `enterInsertMode` first. The "+ new" template (`template` in `drafts-editor-site.mjs`) must match `scripts/new-draft.mjs`. The publish button (`POST /edit/api/drafts/<slug>/publish`) moves a draft into the first `published` folder with `date:` set to today (unless the dialog's "keep its date"), refusing while it has problems or a published post owns the slug, and reports the file, its `public/assets/blog/<slug>/` images and any relative imports in a banner; the site's `publish` hook in `drafts-editor-site.mjs` then drops the `share:` line and adds the `drafts:sync` reminder, so it must match `scripts/publish-draft.mjs`. `editor.html` gets its stylesheets, config JSON and client script injected by the integration (`/@fs/` when the package lives outside the project root). Astro doesn't restart when these files change; restart `npm run dev` after editing `integration.mjs`.
*   **Comments:** self-hosted [Comentario](https://comentario.app) 3.19 at `https://comments.justin-chae.org`, so readers can comment without any account (the user removed giscus because it required GitHub; don't reintroduce GitHub-only comments). It runs on the user's home server from `comments-server/` (see its `README.md`): SQLite, reachable publicly only through a Cloudflare Tunnel, with Comentario's port published only on the Tailscale address and loopback. The domain's policy holds unregistered readers' comments (and any with a link or image) for moderation; Comentario then POSTs a signed webhook (HMAC-SHA256 over `<timestamp>.<body>`, keyed with the secret's hex-decoded bytes) to `comments-server/moderator`, which asks Claude Haiku 5.5 (`claude-haiku-5-5`, effort `low`, a structured-output JSON schema built from its zod `Verdict`) for `approve`/`hold`/`reject` and acts through Comentario's API as a user with the domain's Moderator role. It never auto-approves a comment with a link or image, holds on refusals, errors, and off-schema answers, notifies the user's phone through ntfy for anything that isn't a plain approval, and has a `DRY_RUN` mode; `node src/check.ts` verifies a deployment. The comment text reaches Claude as a JSON string labelled as data, never instructions; keep it that way. `Post.astro` renders `section.post-comments > comentario-comments[data-src][page-id="/blog/<slug>/"][theme=dark][no-fonts=true][max-level=3]`: `page-id` pins the thread to the canonical path (never change its format, or threads detach from their posts), and `no-fonts` makes it inherit the body font. `script.js` §9 appends the widget script from `data-src` when the panel nears the viewport (immediately for a `#comentario-<id>` link) and shows a `.comments-down` line if it can't load. `home.css` maps Comentario's `--cmntr-*` custom properties onto Rosé Pine and restyles the widget to match the site: "Add a comment" is a one-line `>` prompt until clicked, the editor is one bordered box (formatting bar, text, buttons), buttons are flat chips with rose primaries that fill on hover, each comment shows its name and time on one line with no avatar (nearly every commenter is anonymous, so they'd all be the same silhouette) beside a thin rule that collapses its replies, badges are outlined chips, and the RSS button stays hidden (it is the only thing in `.comentario-thread-buttons`; the blog has no feeds). The site-wide `li` (left rule, indent) and `a:hover` (iris fill) rules are reset inside the widget, except for links in comment text. Writing a comment: the editor's footer hints "Markdown · math in $$…$$" (CSS generated content, so MathJax never sees it), the text area draws no focus ring of its own (the box's border shows focus), and while an editor is open the sign-in dialog that "Add Comment" opens for signed-out readers lists its no-account form (name, send) first (`:has(.comentario-comment-editor)` + flex `order`), with `script.js` §9b putting the cursor in the name field. **Math in comments:** readers write `$$…$$` like posts (inline in a sentence, display when it fills a paragraph); §9b swaps each span for a `span.math-inline`/`span.math-display` holding `\(…\)`/`\[…\]` as textContent and typesets just those with MathJax, loading `mathjax-config.js` + the bundle on first use (`startup.typeset: false`) on posts without math. Comentario renders Markdown on its server, which drops the backslash before punctuation (`\{`, `\,`, `\\`) and turns `*…*` into emphasis, so the TeX comes from each comment's own Markdown (one POST to `/api/embed/comments`, the list the widget loads, refetched for comments newer than it) or, in the editor's preview, from its text area; the rendered text is the fallback (e.g. a reader's own pending comment). A MutationObserver on the mount reruns it for new comments, live updates, edits and previews. comentario.css loads after `home.css`, so every override starts with `.post-comments comentario-comments .comentario-root` to win ties, and repeats the `:not()`s of the general button rule when it styles one kind of button — recheck them after a Comentario upgrade. The comments panel is excluded from scroll-reveal. On posts that render comments (`Base.astro` `comments` prop), the `post` CSP allows the comment server's origin in `script-src`, `style-src`, `font-src` (no font is fetched, but Chrome logs a violation per `@font-face` otherwise), `img-src` (avatars, plus `data:` for the widget's CSS icons) and `connect-src` (plus its `wss:` origin for live updates); keep that in sync if the embed changes. Comments only work on `justin-chae.org` itself: Comentario refuses other origins, including `localhost` previews.
*   **Math:** write `$$…$$` in markdown. `remark-math` (`singleDollarTextMath: false`, so a lone `$` stays a dollar sign) parses it like kramdown did: inside a sentence it is inline math; a fenced `$$` block, or a paragraph holding nothing but one `$$…$$`, is display math. `src/plugins/remark-mathjax.js` emits the TeX verbatim as `span.math-inline` `\(…\)` / `div.math-display` `\[…\]`, so backslash escapes (`\;` `\{` `\\`) and `_…_` are safe — write plain LaTeX, never doubled backslashes. It renders client-side by the **self-hosted MathJax 3.2.2 SVG** bundle (`/assets/mathjax/tex-svg.js` + `/assets/mathjax-config.js`, which also accepts `$$…$$` for math in raw HTML). `Post.astro` loads the 2 MB bundle only on posts that contain math (`remarkPluginFrontmatter.hasMath`, set by the plugin); comments load it on their own when one has math (see **Comments**). Because comment TeX comes from strangers, `mathjax-config.js` keeps the `html` extension (`\href`, `\class`, `\style`, `\cssId`) and `\unicode` from being autoloaded or `\require`d; only `tex-svg.js` is self-hosted, so no extension can load in any case. MathJax rejects unknown config options, so recheck a post's math after editing that file. `tsconfig.json` excludes the bundle — type-checking it runs `astro check` out of memory.
*   **Math in `.mdx`:** MDX treats `{ }` as JavaScript, so `$$…$$` with braces breaks there. Use `<Tex tex="p" />` (inline, emits `\(…\)`) or `<Tex block tex={String.raw`…`} />` (display, emits `\[…\]`) from `@/components/blog/Tex.astro`. Also in MDX: no `<!-- -->` comments (use `{/* */}`) and no bare `<` in prose.

no mixture panel or phase list). `Tweet` renders an X post as a static card (full text in the slot, author/handle/date props, an optional `avatar` saved locally under `public/assets/blog/` so no image loads from X, an optional `caption`; Colors use the `--chart-*` tokens in `home.css` (Rosé Pine hues stepped into the dark chart band and validated for colorblind separation and ≥ 3:1 contrast on `--bg`); a color follows its entity across a post, and text never wears a chart hue. Inside `<Grid>` pass `width={340}` (lines) / `width={300}` (bars) so SVG text stays ≥ ~10px on phones; inside `<Grid cols={3}>` pass `width={220}` (bars). `<LineChart full>` spans the whole post column: it ships a 720-unit drawing for wide screens and the compact one below 760px (CSS shows one; `script.js` binds hover per SVG).
*   **Tools (`/tools/`):** tools the user built, each published as its own public GitHub repo (the user wants a public repo for every tool they make). The page's premise, stated in its intro: every tool is written entirely by AI, to test whether "coding is dead". Add a tool by adding `src/content/tools/<id>.md` (front matter: `name`, `description`, `repo`, `stack`, `image: /assets/tools/<id>`, `imageAlt`, `date`) and its two images; the panel id is `<id>`, so `/tools/#<id>` links to it. The page uses the strict CSP, so write-ups can't use fenced code blocks (Shiki's inline styles); inline code is fine. Public repos never carry personal data: copy the tracked files into a fresh repo (new history), check them for keys, tokens, IDs, names and paths, and use made-up data for screenshots.
*   **Syntax highlighting:** Shiki with the `rose-pine` theme (config in `astro.config.mjs`).

## 2. Code Style & Conventions

### HTML (`.astro`)

*   **Indentation:** Use **Tabs**.
*   **Semantics:** deeply prioritized. Use `<nav>`, `<header>`, `<main>`, `<section>`, `<footer>` appropriately.
*   **Attributes:** double quotes; `alt` mandatory for images; `aria-label` for interactive elements without text labels.
*   **Performance:** lazy loading for below-the-fold images; explicit `width`/`height`; hero image keeps `fetchpriority="high"`. YouTube embeds must use the lite pattern (`.video-placeholder` + click-to-load in `script.js`).
*   **Security:** every page sets a `Content-Security-Policy` `<meta>` via `Base.astro` (`strict` for non-post pages; `post` adds `style-src 'unsafe-inline'` for MathJax/Shiki inline styles). External resources require updating the CSP. No inline `style=""` in authored markup; scripts load from `/script.js` (or `is:inline src=` files only).

### CSS (`public/home.css`)

*   **Theme:** Rosé Pine (main variant, https://rosepinetheme.com), terminal-flavored. Dark only, clean flat surfaces — NO CRT effects (scanlines/vignette/grain/glows/gridlines were deliberately removed). All colors via CSS variables in `:root`:
    *   Surfaces: `--bg` (#191724 base), `--bg-raised` (#1f1d2e surface), `--bg-inset` (#26233a overlay)
    *   Text: `--text` (#e0def4), `--subtle` (#908caa), `--muted` (#6e6a86); lines: `--border` (#403d52), `--border-bright` (#524f67)
    *   Accents: `--rose` (#ebbcba cursor/active/h2/focus), `--gold` (#f6c177 dates/labels/chips), `--iris` (#c4a7e7 links), `--foam` (#9ccfd8 mode block/keywords), `--pine` (#31748f quiet structure), `--love` (#eb6f92 errors/404)
    *   Stick to this mapping when adding components; do not reintroduce glows or textured backgrounds.
    *   Charts use the separate `--chart-*` tokens instead: the raw accents are too light and too gray to tell apart as data marks (see **Figures** above).
*   **Type pairing:** `--font-display` (Departure Mono) for headings/nav/statusline; `--font-body` (CommitMono Nerd Font) for copy. ALL fonts are self-hosted subset woff2 in `/assets/fonts/` (see its README) — **never load fonts from Google Fonts**: the site sits behind Cloudflare, whose "Cloudflare Fonts" feature rewrites Google Fonts links into inline `<style>` blocks that the strict CSP blocks (this broke headings in production once). Departure Mono has one weight — never apply `bold` to display type. CommitMono ships 400/700 only — use `font-weight: 700` for bold, never 600.
*   **Korean text:** `assets/fonts/NanumGothicCoding-name.woff2` contains ONLY the three glyphs 채정인. If you add any other Korean text, re-subset it with wider `--unicodes` (see `assets/fonts/README.md`).
*   **Units:** `rem` for font sizes/padding; kebab-case class names; multi-line rules.
*   **Motion:** every animation/transition must have a `prefers-reduced-motion: reduce` override.
*   **Scrollbar gutter:** `html` keeps `scrollbar-gutter: stable`. Without it, short pages (an empty blog, the 404) have no scrollbar and the centered nav and panels shift 5px sideways versus long pages.
*   **Profile photo:** stays in full color — no grayscale/desaturate filter (explicit user request); hover only adds the rose border + shadow.
*   **Cache-busting:** `Base.astro` appends `assetVersion` (`?v=<commit>` from `GITHUB_SHA`, defined in `src/lib/site.ts`) to `/home.css` and `/script.js`, and `index.astro` (the CV button) and `script.js` (`:cv`, reading the version off its own `src`) to the CV, because Cloudflare caches them in browsers for hours (an unversioned CV link kept serving the old PDF after an update). Keep it if you move or rename any of them.

### JavaScript (`public/script.js`)

*   **Indentation:** 4 spaces. Modern vanilla ES6+ (`const`/`let`, arrow functions, template literals, single quotes, semicolons required).
*   **Execution:** wrap logic in `document.addEventListener('DOMContentLoaded', ...)`.
*   **Progressive enhancement:** the site must remain fully readable with JS disabled (typed boot line falls back to static text, sections fall back to visible).
*   **Observers:** Use `IntersectionObserver` for scroll-based effects; throttle scroll handlers with `requestAnimationFrame`.

## 3. Architecture & Patterns

### Interactivity (public/script.js)
*   **Centralization:** All interactivity lives in `public/script.js` (shared by every Astro page). No inline JS in HTML.
*   Features: typed boot line, scroll reveal, lite YouTube embeds, lite X embeds (on post pages, an `x.com`/`twitter.com` `/<user>/status/<id>` link that stands alone in its paragraph becomes a click-to-load placeholder; links inside a sentence stay links; hosts are matched exactly, not by substring; the `post` CSP allows the platform.twitter.com frame), back-to-top, statusline scroll position + showcmd, and vim keyboard navigation (`j`/`k` scroll, `d`/`u` half page, `gg`/`G` top/bottom, `h`/`l` previous/next page (Home → Violin → Blog → Tools, wrapping; `PAGE_ORDER`), `?` help overlay, `Esc` close). The keydown handler must keep ignoring modifier combos, IME composition, and form fields, and the help overlay is built with `createElement` (no `innerHTML`, no inline styles — CSP) and keeps `Tab` inside while open. Scroll reveal applies to `main > section` panels only (never post-content sections such as footnotes) and triggers via a `rootMargin`, not a visibility ratio, so panels taller than the viewport still reveal; print CSS forces unrevealed panels visible. Clipboard writes go through one `copyText()` helper (async API, `execCommand` fallback). On the 404 page `script.js` echoes the requested path into `.err-path`.
*   **Vim command mode (`:`):** pressing `:` opens an ex-style command line docked above the statusline (mode block shows `CMD`). Commands: `:about`/`:education`/`:papers`/`:projects`/`:achievements`/`:service` scroll to sections (navigating to `/index.html#<section>` first when on another page), `:music`/`:blog`/`:tools`/`:home` navigate pages, `:email` copies the contact address to the clipboard, `:cv` opens the CV PDF in a new tab, `:linkedin`/`:scholar`/`:github`/`:x`/`:twitter` open those profiles in a new tab (`noopener`), `:help` opens the key overlay, `:ls` lists sections, `:top`/`:bottom` (+ `:1`/`:$`) scroll, `:noh`/`:nohlsearch` clears search highlights, and `:q`/`:q!`/`:wq` are deliberate easter eggs. Like vim, `Enter` runs the line and returns to normal mode; `Esc` or clicking elsewhere on the page also closes it (switching windows does not). Supports `↑`/`↓` history (consecutive duplicates collapsed) and `Tab` prefix completion with candidate list. `closeCommandLine()` blurs the input explicitly — browsers only move focus off a hidden element on the next frame, which swallowed fast keystrokes. Unknown commands echo `E492: not an editor command: <name>` in the `--love` color. Feedback is echoed into `#showcmd` (`.flash-msg`/`.err` classes) AND mirrored into a `.visually-hidden` `aria-live` region — keep both when editing.
*   **Vim search (`/`, `n`, `N`):** `/` opens the same docked command line in SEARCH mode; Enter runs a case-insensitive substring search over `<main>` text and wraps hits in `mark.search-hit` (`.current` = rose; `n`/`N` cycle and auto-open collapsed `details`/reveal hidden sections; empty Enter reuses the last pattern). Misses echo `E486: pattern not found`, `n` with no prior search echoes `E35`. Highlights clear via `:noh` or a new page load. Keep the `prefers-reduced-motion` (pulse) and print (transparent) overrides when editing.
*   **Blog trace blocks (Prime Intellect-style):** in a post, wrap code blocks or prose in directive containers — `:::tool-call` / `:::tool-output` / `:::annotation` / `:::reasoning` (starts collapsed) / `:::bibtex` (unnumbered) / `:::tldr` — and the `remarkTraceDirectives` plugin puts the class on the wrapper. On post pages `script.js` wraps each container in a numbered collapsible `details.trace-block` panel (steps run in document order across mixed code/prose; every type accepts prose, which gets the padded `.trace-prose` well) and every `pre` gets an overlay `[copy]` button (`.copied`/`.err` feedback states). Footnotes via `[^1]`/`[^1]: text` (GFM) render as a `~/footnotes` well; the CSS targets GFM's markup (`section.footnotes`, `a[data-footnote-ref]`, `a[data-footnote-backref]`, the `.sr-only` heading), not kramdown's. Plain code blocks stay unnumbered. Without JS everything degrades to normal code blocks/paragraphs.
*   **Blog chart hover (`script.js` §11):** `LineChart` figures carry a `data-chart` payload (pixel positions plus preformatted values). `script.js` adds a crosshair + tooltip on pointer or keyboard focus (←/→ step through points, Esc hides) and writes text with `textContent` only. Without JS the static chart remains.
*   **Animated diagrams (`script.js` §12):** `SelfPlayAnimation` draws the complete static diagram in markup; script.js adds `.sp-live` and runs one clock over `data-cycle` seconds, toggling `.is-shown` (from `data-on`/`data-off`), `.is-active` (from `data-active="start end"`, which may list several pairs), moving packets (`data-travel` + `data-route` points) and typed text (`data-type="start end"`: the element's text is read once, then revealed character by character over that window). Pause/restart only move the clock; it plays while ≥35% on screen. Under `prefers-reduced-motion` (or without JS) nothing runs and the static diagram stays. `AgentReplay` uses the same clock (`.sp-anim`), mapping agent turns linearly to seconds (its data gives each job's launch and result turn, plus the same moments in hours), with a `data-ease="linear"` playhead; its static state is the end of the run (CSS hides every `.ar-frame` and `.ar-best` but the `.ar-final` one until `.sp-live`). Its controls carry a `[data-sp="speed"]` button (cycles the clock's pace through 0.5×, 1×, 2×, 4×; the scrubber and `.sp-time` stay in step because only the clock's rate changes), a `.sp-scrub` range input (`step="any"` so the thumb glides; script.js handles keys itself: arrows 2% of the loop, Page keys 10%, Home/End; it pauses while dragging, keeps a 0.12s fade, and resumes on release if it was playing) and a `.sp-time` readout (`data-offset`/`data-rate`/`data-max` turn seconds back into the figure's units, labelled by `data-unit` with `data-digits` decimals, e.g. "turn 93"; also used as the slider's `aria-valuetext`). A figure with a scrubber still runs under reduced motion, parked at its end state and never autoplayed.
*   **Blog post anatomy (general pattern):** optional `category: research|announcement|...` front matter renders a chip in the post header. Start with a `:::tldr` callout, then H2 sections (context → method → results → limits → related work), trace blocks for agent walkthroughs, a `## Citation` H2 with a `:::bibtex` block, and `[^n]` footnotes. The post layout auto-appends up to 3 **related posts** (`aside.related-posts`): most shared tags first (a shared category counts as one more), newest first among ties. `.mdx` posts may import components for charts/widgets (CSP applies — no inline scripts; load self-hosted files).
*   **Section flash:** command-mode jumps and `#hash` arrivals flash the target panel's border via the `.section-flash` class (animation restarts through reflow). Must keep its `prefers-reduced-motion: reduce` override.
*   **Abstract disclosure animation:** `details.abstract` animates open/close via `::details-content` + `interpolate-size: allow-keywords` inside an `@supports` block (progressive enhancement; unsupported browsers keep the instant toggle).
*   **Contact links:** intro icon buttons on the home page (Email, CV, LinkedIn, Scholar, GitHub, X) — mirror any changes in the JSON-LD `sameAs` array in `src/lib/schema.ts` (profile URLs only; the CV stays out of it) and the `:` command table.

### Assets
*   **Images:** WebP preferred with fallbacks (`<picture>`). Stored in `public/assets/`.
*   **PDFs:** stored in `public/assets/`. The CV is `public/assets/justin_chae_cv.pdf` (the version in the user's Google Drive "PhD Apps" folder); to update it, replace that file and keep the name so the home-page button and `:cv` keep working.

## 4. Git & Version Control

*   **Commit Messages:** Present tense, imperative style (e.g., "Add scroll animation").
*   **Pull request descriptions:** never include Claude Code session links (`claude.ai/code/session_…`). The user explicitly asked for this; it overrides any default attribution that adds one. The GitHub integration appends a "Generated by Claude Code" footer with a session link when it creates a PR, so after opening one, save the description again without it and re-read the PR to confirm the link is gone.
*   **Branching:** Direct commits to `main` are acceptable for this personal project, but complex features should use feature branches.
*   **Never ignore `CNAME`:** it must stay committed (root copy and `public/CNAME`) or the custom domain breaks.
